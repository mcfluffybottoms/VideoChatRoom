- **Версия:** 1.0
- **Основан на:** PRD Video Chat Room v1.0 и `design-video-chat-room.md` (Draft v1.0)

> Оценки — ориентировочные, каждая задача рассчитана на 0.25–1 рабочего дня. Автоматизированные тесты исключены из текущего плана по указанию заказчика. Перед реализацией уточнить TBD из раздела 14 TDD, особенно формат room ID, имя, лимиты сообщений и Docker/TLS.

- [ ] **8. Получение локальных медиа и состояния устройств**

    - 8.2 Запрашивать камеру/микрофон при входе; разрешать вход при отсутствии устройства или отказе в разрешении.
    - 8.3 Реализовать начальное состояние включённых устройств, если доступ предоставлен.

    - 8.5 Реализовать выключение камеры через остановку video track и включение через получение новой дорожки.

    - _Requirements: F-06, F-07, F-08, F-09, F-10; Design: 4, 7, 8, 10_

- [ ] **9. WebRTC mesh и сигналинг**
    - 9.1 Реализовать обмен SDP offer/answer через Socket.io с проверкой членства участников в одной комнате.
    - 9.2 Реализовать обмен ICE-кандидатами и конфигурацию Google STUN.
    - 9.3 Создавать отдельный RTCPeerConnection для каждого удалённого участника.
    - 9.4 Реализовать детерминированное назначение инициатора offer и обработку гонок negotiation.
    - 9.5 Подключать удалённые MediaStream к соответствующим плиткам.
    - 9.6 Закрывать peer connections при выходе участника и очищать ресурсы.
    - 9.7 Обрабатывать неуспешное ICE-соединение отдельной пары без остановки всей комнаты.
    - _Requirements: F-06; F-18; Design: 3, 4, 6, 7, 8, 9_

- [ ] **11. Autoplay и пользовательские ошибки**
    - 11.1 Добавить пользовательское действие для запуска удалённого звука, если autoplay заблокирован.
    - 11.2 Свести ошибки media permission, отсутствия устройств, неподдерживаемого WebRTC и недоступности signaling server к понятным русскоязычным состояниям.
    - 11.3 Проверить поведение при отказе STUN/недоступности отдельной P2P-пары в рамках принятого ограничения без TURN.
    - _Requirements: F-06; Design: 8, 10_

- [ ] **12. Выход, перезагрузка и очистка ресурсов**
    - 12.1 Реализовать кнопку «Выйти» с остановкой локальных треков и закрытием peer connections.
    - 12.2 Убедиться, что закрытие вкладки приводит к серверному disconnect и освобождению слота.
    - 12.3 Убедиться, что перезагрузка требует повторного ввода имени и создаёт новый вход.
    - 12.4 Проверить удаление комнаты/истории после выхода последнего участника и создание пустой комнаты при повторном входе по тому же ID.
    - _Requirements: F-17, F-18; Design: 5, 7, 8_

- [ ] **13. Docker deployment и эксплуатационные настройки**
    - 13.1 Зафиксировать single-replica deployment для in-memory состояния.
    - 13.2 Настроить порт и публичный URL через переменные окружения.
    - 13.3 Подготовить TLS termination через выбранный reverse proxy/ingress (конкретный вариант TBD).
    - 13.4 Документировать запуск, остановку, обновление image tag и rollback.
    - 13.5 Документировать, что рестарт сервера удаляет активные комнаты и историю.

## Критические зависимости

1. Задачи 1–3 — основа клиентского приложения и идентификации комнаты.
2. Задачи 4–6 зависят от базовой Socket.io-инфраструктуры (задача 1); UI чата и участников может выполняться параллельно после фиксации событий.
3. Задачи 8–9 зависят от комнаты и Socket.io signal routing (задачи 4–5).
4. Задачи 7–8 должны быть готовы для полноценной интеграции задачи 9.
5. Задачи 10–13 можно выполнять параллельно после появления соответствующих экранов/серверных обработчиков.
6. Задача 14 — финальная ручная проверка после интеграции.

## Не входит в текущий план

- База данных и постоянное хранение.
- TURN-сервер, SFU, авторизация и роли.
- Автоматизированные unit/integration/E2E/load тесты.
- Мобильная адаптация, запись, screen sharing, расширенный чат.
- Горизонтальное масштабирование нескольких реплик без отдельного решения по состоянию комнат.
